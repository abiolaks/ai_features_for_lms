The Core Principle 

AI01 is the foundation that powers every AI feature on the platform. 

The platform operates on one simple chain: 

Course is published → Content is indexed → AI features query the index → Huawei MaaS generates the response 

  

No AI feature works without AI01 being live first. It is the data layer everything else sits on top of 

Multi-Tenant Isolation 

Every organisation on the platform gets its own isolated data boundary inside Cloudflare AI Search. This is done using namespaces. 

Think of it like this: 

- Cloudflare Account is the container for everything 

- Namespace = one per organisation (e.g. org-wragby, org-acme) 

- Instance = a category of content within that organisation (courses, lessons, assessments) 

Organisation A can never see, access, or accidentally receive content from Organisation B. This is enforced at the infrastructure level, not just in application code. 

Each organisation gets three content buckets: 

- Courses instance — course titles, descriptions, prerequisites, metadata 

- Lessons instance — full lesson content: video transcripts, reading material, headings, timestamps 

- Assessments instance — quiz questions, rubrics, marking criteria 

AI01: How New Course Content Gets Indexed Automatically 

This uses an event-driven webhook pattern. The AI Search service does not poll the database looking for new content. Instead, the platform pushes content to it the moment something is published. 

The full flow when an admin publishes a course: 

1. Admin clicks "Publish" on a course inside the platform 

2. The platform backend fires a notification event (webhook) to a Cloudflare Worker 

3. The Worker receives the course data — all lessons, transcripts, readings, and assessment questions 

4. The Worker breaks the course into logical pieces per lesson and per assessment 

5. Each piece is uploaded to the correct AI Search instance under that organisation's namespace 

6. AI Search automatically handles the rest: chunking content into smaller segments, converting it to searchable vectors, and building a keyword index 

7. Within seconds, the content is live and every AI feature can query against it 

When a lesson is edited and re-published, the same process runs and overwrites the previous version — the index stays current automatically. 

When a course is unpublished or deleted, the platform sends a delete event and the content is removed from the index. 

There is no manual indexing step. From the admin's perspective, publishing a course and it becoming AI-queryable is the same action. 

Huawei MaaS: The AI Brain 

Cloudflare AI Search handles finding the right content. Huawei MaaS handles writing the response. 

These are always two separate steps: 

1. Retrieve — query AI Search and get back the most relevant content chunks 

2. Generate — pass those chunks to Huawei MaaS and ask it to produce an answer, recommendation, or plan 

Huawei MaaS is registered inside Cloudflare AI Gateway as a custom provider. This means all calls to Huawei MaaS go through AI Gateway, which provides cost tracking, caching (so the same query is not billed twice), rate limiting, and automatic fallback if Huawei MaaS is unavailable. 

 

Search Modes 

AI Search supports three modes. The platform should use Hybrid for all production queries: 

- Vector search — understands meaning. "How do I deploy my app?" matches lessons about "deployment" even if those words do not appear exactly. 

- Keyword search — matches exact terms. Good for error codes, technical terms, or precise titles. 

- Hybrid — runs both in parallel and merges results. Best accuracy for all query types. 

How Each AI Feature Works End to End 

AI-04 — In-Lesson Grounded Q&A (Lesson Tutor) 

What the learner experiences: 

While watching a video or reading a lesson, the learner opens a panel and types a question about what they are studying. They receive an answer with a reference to exactly where in the lesson that information came from — a section heading or a video timestamp. 

What happens behind the scenes: 

1. Learner types: "What is gradient descent?" 

2. The system queries the AI Search lessons instance, scoped strictly to the current lesson ID 

3. AI Search returns the most relevant content chunks from that lesson only 

4. Those chunks are sent to Huawei MaaS with a strict instruction: answer using only this content, nothing else 

5. If the answer exists in the lesson, Huawei MaaS writes the response and the citation (e.g. "Video — 4m 32s" or "Section: Optimisation Fundamentals") is attached 

6. If the answer does not exist in the lesson, the system responds: "This is not covered in this lesson" — it will not invent an answer 

7. The learner sees the answer and the source reference in the lesson panel 

  

The non-negotiable rule for this feature: The AI is strictly forbidden from using any knowledge outside the indexed lesson content. The grounding is enforced by the system prompt sent to Huawei MaaS, which only provides the retrieved chunks as context. 

 

 

 

The Gaps That Will Hurt AI Quality 

Tags and skillsCovered are empty on every course. In the catalogue response, both tags: [] and skillsCovered: [] are blank across all courses. These fields are critical for AI-03 (recommendations) and AI-02 (learning path generation). Without them, the AI has to rely entirely on the course title and description to match learners to courses. The recommendations will work but will be less precise. 
Action required: Before AI features go live, content admins need to populate tags and skills covered on all published courses. This should be a content requirement, not a technical one.
